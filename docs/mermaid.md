# Mermaid

[Mermaid](https://mermaid.js.org) — текстовые диаграммы, которые отображаются на GitHub, GitLab, в Notion,
Obsidian, Confluence и генераторах документации. Animated Diagrams читает и пишет два вида Mermaid:

- **flowchart / graph** — структура: узлы и связи;
- **sequenceDiagram** — сценарий: кто кому что отправляет и в каком порядке. При импорте он становится
  анимацией.

## Импорт

«Файл → Импорт из Mermaid…» (`Ctrl+Shift+I`): текст можно вставить (если в буфере обмена Mermaid, он
подставится сам) или открыть файл `.mmd` / `.mermaid` / `.md`. Файлы с этими расширениями также открываются
через «Открыть», перетаскиванием и из командной строки. Документ открывается в новой вкладке.

Текст разбирает [merman](https://github.com/Latias94/merman) — реализация Mermaid на Rust (без браузера и
Node.js), совместимая с mermaid.js: синтаксис, ошибки и раскладка — как у Mermaid. Ошибка показывает строку
и столбец.

### flowchart

| Mermaid | Animated Diagrams |
|---|---|
| `A[текст]`, `A[[...]]`, `A>...]` и другие прямоугольные | Сервис |
| `A(...)`, `A([...])` (stadium) | Сервис со скруглённой формой |
| `A[(...)]` (cylinder), `@{ shape: db }` | БД |
| `@{ shape: h-cyl }` (горизонтальный цилиндр) | Очередь |
| `A{...}` (ромб) | Решение |
| `A{{...}}` | Сервис, шестиугольник |
| `A((...))`, `A(((...)))` | Сервис, эллипс |
| `A[/.../]`, `A[\...\]`, трапеции | Сервис, параллелограмм |
| `@{ shape: doc }`, `docs` | Документ |
| `@{ shape: cloud }` | Облако |
| `@{ shape: brace }`, `comment` | Заметка |
| `-->`, `---`, `--o`, `--x`, `<-->` | связь со стрелкой / без / кружком / открытой стрелкой / двусторонняя |
| `-.->` / `==>` | пунктир / толстая линия |
| `-->\|текст\|` | подпись связи |
| `style`, `classDef` + `class`, `linkStyle` | цвета заливки, обводки, текста, толщина, пунктир |

Узлы ставятся так, как их раскладывает Mermaid (с учётом `LR` / `TB` и subgraph), с отступами под размер
наших элементов. Рамки `subgraph` не импортируются: их узлы остаются, в отчёте об импорте есть предупреждение.
`<br>` в подписи делит её на заголовок и подзаголовок, HTML и Markdown внутри подписей убираются.

### sequenceDiagram

| Mermaid | Animated Diagrams |
|---|---|
| `participant`, `actor`, `participant X as Имя` | узлы в ряд (actor — «Пользователь», database / collections — «БД», queue — «Очередь») |
| `A->>B: текст` | сообщение «запрос» по связи A–B (связь создаётся) |
| `A-->>B` (пунктир) | «ответ»; с кодом `2xx` — «успех», `4xx` / `5xx` — «ошибка» |
| `A-xB`, `A--xB` | «ошибка» |
| `A-)B` | «событие» (асинхронное) |
| текст, начинающийся с `retry` | «повтор» |
| `A->>A: текст` | действие на узле |
| `Note left of / right of / over` | заметка рядом с участником |
| `activate` / `deactivate`, `+` / `-` | состояние «Активен» на это время |
| `par` / `and` | ветки идут одновременно |
| `loop`, `alt` / `else`, `opt`, `critical` / `option`, `break` | маркер (глава) с подписью, например «alt: card ok» |
| `autonumber` | номера в подписях сообщений |
| `title` | название документа |

Шаги идут друг за другом: сообщение — 1 с, действие — 0,9 с. Связи между несоседними участниками огибают
ряд дугой. Затем сценарий правится как обычно: длительности, эффекты, таймеры.

### Markdown

В `.md` читаются блоки ` ```mermaid ` (и `~~~mermaid`). Если есть flowchart и sequenceDiagram, первый задаёт
узлы, связи и расположение, второй — сценарий: участники совпадают с узлами по id. Так устроен файл,
который пишет экспорт в Markdown, поэтому он импортируется обратно почти без потерь. Блоки других типов
(classDiagram, gantt, …) пропускаются с предупреждением.

## Экспорт

«Файл → Экспорт» → формат **Mermaid**, затем вид диаграммы:

- **Flowchart (.mmd)** — узлы с формой по типу элемента, связи с подписями, стрелками, пунктиром и цветами
  (`style`, `linkStyle`). Комментарии `%% ad:pos id x y` хранят точные координаты для обратного импорта
  (Mermaid их игнорирует).
- **Sequence diagram (.mmd)** — сценарий:
  - участники — узлы, которые в нём задействованы, слева направо;
  - сообщения — стрелки по виду: запрос `->>`, ответ `-->>`, ошибка `-x`, событие `-)`;
  - действия — сообщение самому себе;
  - заметки — `Note over` ближайшего участника;
  - таймеры — `Note over X: ⏱ 5s timeout`, смены состояния — `Note over X: ● down`;
  - маркеры — `Note over A,Z: ⚑ глава`;
  - одновременные шаги — блок `par`;
  - эффекты и анимации связей — комментарии.
- **Markdown (.md)** — заголовок, описание и обе диаграммы в блоках ` ```mermaid `: такой файл можно
  положить в репозиторий или вставить в README.

Тайминг, эффекты и точный вид в Mermaid упрощаются: Mermaid — статичный формат. Для анимации есть GIF, видео,
PowerPoint и HTML-плеер ([Презентации](presentations.md)).

## Командная строка и MCP

```bash
animated-diagrams --convert flow.json flow.mmd                 # Mermaid → .json
animated-diagrams --export flow.gif checkout.mmd               # sequenceDiagram → анимированный GIF
animated-diagrams --export docs/flow.md diagram.json           # обе диаграммы в Markdown
animated-diagrams --export seq.mmd --mermaid sequence diagram.json
```

MCP: `import_mermaid {text | path, keepColors}`; `to_mermaid {kind}` возвращает текст без записи файла;
`export_animation {path, format: "mermaid", mermaidKind}`. Агенту удобно набросать сценарий как
sequenceDiagram, импортировать его и дальше дорабатывать инструментами.

## Сборка

Импорт требует Rust 1.95+ (`cargo`, [rustup](https://rustup.rs)). merman собирается из crates.io через
[Corrosion](https://github.com/corrosion-rs/corrosion) и линкуется статически. Обёртка лежит в
`third_party/merman`, версии зафиксированы в `Cargo.lock`. Без Rust соберите с `-DWITH_MERMAID=OFF`:
экспорт в Mermaid останется, импорт будет недоступен.
