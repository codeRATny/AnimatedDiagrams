# Презентации

## Веб-презентации: HTML-плеер

Экспорт **«HTML-плеер»** создаёт одну самодостаточную HTML-страницу: внутри документ (JSON со встроенными
определениями плагинов — как при сохранении), движок приложения, скомпилированный в WebAssembly, и
рендерер на `<canvas>`. Кадры рисует тот же код, что и в редакторе (`ad_engine`), поэтому анимация
совпадает с экспортом GIF / видео, но остаётся векторной и чёткой на любом экране (учитывается
`devicePixelRatio`), а размер файла не зависит от длины сценария (≈ 330 КБ + документ, ≈ 150 КБ в gzip).
Сеть не нужна: страница работает из `file://`, с любого статического хостинга и внутри `<iframe>`.

```bash
animated-diagrams --export diagram.html diagram.json            # или «Файл → Экспорт» → «HTML-плеер»
animated-diagrams --export diagram.html --no-loop --no-autoplay diagram.json
```

MCP: `export_animation {path: "diagram.html"}` или `{format: "html", loop, autoplay}`.

### Управление

| | |
|---|---|
| Клик по диаграмме, `Space`, `→`, `PageDown` | следующий сегмент: проиграть до следующего маркера и остановиться (во время проигрывания сегмента — сразу к его концу); без маркеров — пуск / пауза |
| `←`, `PageUp` | к началу текущего / предыдущего сегмента; без маркеров — на 1 с назад |
| `Home` / `End` | начало / конец |
| `K` | пуск / пауза (непрерывно, без остановок на маркерах) |
| `L` | повтор вкл / выкл |
| `Esc` | снять фокус с плеера |

Панель (появляется при наведении): предыдущий / следующий сегмент, пуск / пауза, перемотка с
отметками маркеров (кликабельны), время и номер сегмента, повтор. Сегменты задаются маркерами сценария
(`scenario.markers` — время в мс); если маркеров нет, кнопки сегментов скрыты.

### Параметры

Параметры URL (`diagram.html?autoplay=0&controls=1`) или `data-*` атрибуты элемента `#ad-player`
переопределяют значения, выбранные при экспорте:

| Параметр | Значения | По умолчанию |
|---|---|---|
| `autoplay` | `1` / `0` — начать проигрывание при открытии (с маркерами — только первый сегмент) | как при экспорте (`prefers-reduced-motion` отключает, если не задано явно) |
| `loop` | `1` / `0` | как при экспорте |
| `controls` | `auto` (при наведении / фокусе), `1` (всегда), `0` (скрыты; клавиши и клик работают) | `auto` |
| `segment` | номер сегмента, с которого начать (1 — начало) | — |
| `t` | время начала, секунды | `0` |
| `speed` | скорость, `0.1`…`8` | `1` |
| `keys` | `focus` — клавиши только когда плеер в фокусе; `1` — все нажатия на странице; `0` — без клавиатуры | `focus` во фрейме, `1` на отдельной странице |
| `src` | URL документа JSON для «пустого» шаблона `player.html` (без встроенного документа) | — |

**Фокус в слайдах.** Во `<iframe>` плеер не перехватывает клавиши презентации, пока по нему не кликнули
(`keys=focus`). После клика стрелки и пробел управляют сегментами; чтобы вернуть клавиши презентации,
кликните по слайду вне диаграммы (или `Esc`, затем клик). `keys=1` — плеер реагирует на любые нажатия,
пока фокус внутри фрейма.

**Управление со страницы.** Плеер принимает `postMessage`:
`{type: "ad-player", action: "play" | "pause" | "toggle" | "next" | "prev" | "restart" | "seek", time}`
(`time` — мс для `seek`). Сообщения reveal.js `slide:start` / `slide:stop` (их получают все `<iframe>`
слайда) перезапускают плеер с начальной позиции / ставят на паузу.

### reveal.js

```html
<section>
  <h2>Повтор запроса с fallback</h2>
  <iframe data-src="diagrams/fallback.html?controls=auto" width="960" height="540"
          style="border:0" data-preload></iframe>
</section>
```

При показе слайда reveal.js отправляет фрейму `slide:start` — анимация начинается заново, при уходе —
`slide:stop`. Для полноэкранного фона: `<section data-background-iframe="diagrams/fallback.html?controls=0"
data-background-interactive>`.

### Slidev

```md
---
layout: center
---

# Повтор запроса с fallback

<iframe src="/diagrams/fallback.html?autoplay=1" class="w-full h-110 border-0" />
```

Файл кладётся в `public/diagrams/`. Вместо `<iframe>` можно использовать layout `iframe`
(`url: /diagrams/fallback.html`).

### Marp

```md
---
marp: true
---

# Повтор запроса с fallback

<iframe src="diagrams/fallback.html?controls=1" width="100%" height="480" style="border:0"></iframe>
```

HTML-теги в Marp нужно разрешить: Marp CLI `--html`, в VS Code — настройка `markdown.marp.enableHtml`.
Плеер работает в HTML-экспорте Marp;
в PDF / PPTX из Marp `<iframe>` не переносится — там используйте GIF или MP4.

### Обычная страница, wiki, документация

```html
<iframe src="fallback.html" width="800" height="450" style="border:0" loading="lazy"
        title="Повтор запроса с fallback"></iframe>
```

Размер фрейма любой: диаграмма вписывается целиком (как «По содержимому» при экспорте) и
перерисовывается при изменении размера. Страницу можно открыть и напрямую — тогда клавиши работают без
клика.

### PowerPoint

В PowerPoint (Microsoft 365, в том числе PowerPoint для веба) веб-страницу показывает надстройка
**Web Viewer** («Вставка → Надстройки → Web Viewer»): опубликуйте `diagram.html` на HTTPS-адресе
(GitHub Pages, внутренний веб-сервер, любое статическое хранилище, которое разрешает показ во фрейме) и
вставьте ссылку. Файлы с диска (`file://`) и HTTP надстройка не открывает. Анимация проигрывается в режиме
показа слайдов; для слайдов без интернета используйте экспорт MP4.

### Сборка плеера

Плеер собирается Emscripten из `player/` и того же `ad_engine`, что и приложение; приложение встраивает
готовый `player.html` как ресурс (без него формат HTML не предлагается):

```bash
git clone https://github.com/emscripten-core/emsdk && cd emsdk
./emsdk install 6.0.10 && ./emsdk activate 6.0.10 && source ./emsdk_env.sh && cd -
emcmake cmake -S . -B build/player -G Ninja        # или: cmake --preset player (нужен $EMSDK)
cmake --build build/player                          # → build/player/player/player.html
cmake -S . -B build/release -DAD_PLAYER_HTML=$PWD/build/player/player/player.html ...
```

Шаблон без документа можно открыть по HTTP с параметром `?src=diagram.json` — удобно при отладке плеера.

### Ограничения

- **Шрифты.** Текст рисует браузер системным шрифтом (`system-ui`, затем Segoe UI / Roboto / Noto Sans /
  Arial) или семейством из дизайн-системы, если оно установлено у зрителя; веб-шрифты не встраиваются.
  Ширина подписей измеряется тем же шрифтом (`measureText`), так что раскладка согласована, но метрики
  могут немного отличаться от редактора. Эмодзи и значки зависят от шрифтов системы.
- **Свечение и тени** повторяют рендер приложения (несколько полупрозрачных обводок), без размытия.
- Встроенные подписи состояний («Normal», «Down» и т. п.) — на английском, подписи документа — как в нём.
- Нужен браузер с WebAssembly и обработкой исключений Wasm (Chrome / Edge 95+, Firefox 100+, Safari 15.2+).
