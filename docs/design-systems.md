# Дизайн-системы

Дизайн-система — набор правил оформления для всего документа: цвета холста, **цветовые токены**, цвета
состояний узлов и вариантов сообщений, шрифт, стиль узлов и связей по умолчанию и переопределения для
отдельных типов элементов. Сменив дизайн-систему, вы меняете вид всей диаграммы, не трогая сами узлы.

## Как пользоваться

- **Выбрать**: снимите выделение — в инспекторе «Сцена → Дизайн-система». Применение отменяется `Ctrl+Z`.
- **Создать / изменить**: «Библиотека» (`Ctrl+L`) → вкладка «Дизайн». «Создать» берёт текущий вид документа;
  встроенные и плагинные системы только для чтения — «Дублировать» создаёт редактируемую копию в документе.
  Справа — живое превью (узлы, сообщение, смена состояния).
- **Сохранить вид**: инспектор сцены → «Сохранить вид как…».
- **Поделиться**: «Экспорт в плагин» — дизайн-системы входят в плагины наравне с элементами и эффектами.
- **Агентам**: MCP `set_scene {designSystem: "light"}`, `list_library {kind: "designSystems"}`,
  `upsert_library_item {kind: "design-system", definition: {...}}`.

Встроенные: «Тёмная (по умолчанию)», «Светлая», «Чертёж», «Высокий контраст». Плагины в комплекте добавляют
«ClickHouse» (Data platform) и «Терминал» (Security kit).

## Порядок применения стилей

```
стиль по умолчанию дизайн-системы (node)
  < стиль типа элемента
  < переопределение типа в дизайн-системе (elements.<type>.style)
  < стиль конкретного узла
```

Для связей: `edge` дизайн-системы < стиль связи. Цвета холста (фон, связи, текст, сетка) при выборе системы
**копируются** в настройки сцены и дальше редактируются отдельно.

## Цветовые токены

В любом цвете (заливка и обводка типа или узла, акцент, цвет шага, цвет эффекта, цвета состояний) можно
писать ссылку на токен `$имя`. Значение берётся из активной дизайн-системы, а если там его нет — из
стандартного набора:

| Токен | По умолчанию | Назначение |
|---|---|---|
| `$surface` | `#3b4a63` | тело узла |
| `$surface-alt` | `#1e293b` | второстепенные поверхности |
| `$border` | `#5a6b86` | обводка |
| `$text`, `$muted` | `#f2f6ff`, `#b7c6e4` | текст, второстепенный текст |
| `$primary`, `$secondary`, `$accent` | `#4f8cff`, `#a855f7`, `#22d3ee` | акценты |
| `$success`, `$warning`, `$danger`, `$info` | `#22c55e`, `#f59e0b`, `#ef4444`, `#38bdf8` | статусы |

Элементы плагинов Data platform и Security kit написаны на токенах — попробуйте переключить дизайн-систему.

## Формат

```jsonc
{
  "id": "sunset", "label": "Закат", "category": "Мои", "description": "…",
  "background": "#2a1020", "edgeColor": "#a86b7d", "textColor": "#fff4ec",
  "grid": true, "gridSize": 24,
  "fontFamily": "DejaVu Sans Mono",           // пусто — шрифт приложения
  "subtitleColor": "#e8b9a8",
  "colors":   { "surface": "#3a1a2c", "primary": "#ff7a59", "brand": "#ffb347" },
  "states":   { "down": { "fill": "#4a1020", "ring": "$danger" } },   // ok active busy warn down success disabled
  "variants": { "request": "$primary", "event": "#c084fc" },           // request response retry error success event
  "node":     { "cornerRadius": 4, "shadow": false },                  // NodeStyle
  "edge":     { "routing": "orthogonal", "width": 1.5, "arrowEnd": "open" },
  "elements": { "db": { "accent": "$brand", "style": { "fill": "#2a2030" } } }
}
```

Документ хранит id активной системы в `"designSystem"`, а свои системы — в `library.designSystems`
(используемая система из плагина при сохранении встраивается в файл).
